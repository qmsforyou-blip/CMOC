## PATCH REG-001

| ID | Type | Различение | Источник | Status |
|---|---|---|---|---|
| **DIS-0497** | NEW | Следует различать **результат проверки** и **незафиксированное наблюдение**. Результаты Error Proofing Verification должны быть записаны. | GM QSB 6.2 | |
| **DIS-0498** | NEW | Следует различать **отказ устройства защиты от ошибок** и **обычное наблюдение**. Отказ требует немедленной реакции. | GM QSB 6.2 | |
| **DIS-0499** | NEW | Следует различать **журнал отказов** и **план реагирования**. Журнал фиксирует failure, а reaction plan задаёт реакцию на связанное несоответствие. | GM QSB 6.2 | |
| **DIS-0500** | NEW | Следует различать **реакцию** и **локализацию (containment)**. Containment является составной частью reaction plan. | GM QSB 6.2 | |
| **DIS-0501** | NEW | Следует различать **уведомление о несоответствии** и **эскалацию реакции**. Для них должна быть предусмотрена процедура. | GM QSB 6.2 | |
| **DIS-0502** | NEW | Следует различать **немедленную реакцию на отказ** и **корректирующее действие**. Corrective Action Report предназначен для предотвращения повторного отказа устройства. | GM QSB 6.2 | |
| **DIS-0503** | NEW | Следует различать **момент обнаружения отказа** и **границу потенциально затронутой продукции**. При отказе продукция должна быть проверена обратно до последней успешной проверки. | GM QSB 6.2 | |
| **DIS-0504** | NEW | Следует различать **реакцию на отказ Error Proofing Device** и **управление несоответствующей продукцией**. SOURCE связывает реакцию с Strategy 2.0 Control of nonconforming product. | GM QSB 6.2 | |
| **DIS-0505** | NEW | Следует различать **операционный результат проверки** и **информацию для руководства**. Verification results должны рассматриваться руководством площадки. | GM QSB 6.3 | |
| **DIS-0506** | NEW | Следует различать **передачу информации руководству** и **способ её отображения**. Для обоих аспектов должен быть определён метод. | GM QSB 6.3 | |
