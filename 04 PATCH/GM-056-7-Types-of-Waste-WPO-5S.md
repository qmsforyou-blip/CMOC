## 1. SOURCE

SOURCE задаёт назначение блока 4.3:

- определить, что такое **tangible waste**;
- разработать процесс и определить способы устранения потерь;
- разработать стратегию 5-S;
- применять 5-S к рабочей среде;
- мониторить / измерять процесс устранения потерь. fileciteturn165file1

В блоке Elimination of Waste GM различает **Value Added Work**, **Non Value Added Work** и Waste. Value Added Work определяется как работа, непосредственно добавляющая ценность продукту; часть Non Value Added Work необходима, но ненужная Non Value Added Work является waste. GM формулирует waste как любой ненужный шаг при выполнении работы. fileciteturn166file5

Для 7 Types of Waste SOURCE использует память **COMMWIP**. В последовательности страниц раскрываются:

- **Correction** — дополнительные ресурсы для исправления;
- **Overproduction** — избыток деталей/информации слишком рано или слишком быстро;
- **Motion** — ненужные движения человека или машины;
- **Transportation** — ненужная транспортировка, хранение или перестановка;
- **Waiting** — пребывание без выполнения относящейся к задаче работы;
- **Inventory** — избыток того, что занимает место, может устаревать и создавать дополнительные потери;
- **Processing** — работа, которую заказчик не воспринимает как добавляющую ценность. fileciteturn166file4turn166file5turn166file6

GM отдельно противопоставляет реакцию на крупные примеры waste систематическому поиску многих малых возможностей: **Waste is tangible → Identify Many Small Opportunities → Continuous Improvement**. fileciteturn166file13

## 4. DISTINCTIONS — РАЗЛИЧЕНИЯ

### 4.1 Value Added ≠ Non Value Added ≠ Waste

GM сначала требует различить эти категории. Не вся Non Value Added Work автоматически считается Waste: часть такой работы может быть необходимой. Waste — ненужная часть Non Value Added Work. fileciteturn166file5

### 4.2 Waste ≠ только большой видимый дефект

SOURCE противопоставляет реакцию на крупные примеры выявлению множества малых возможностей.

### 4.3 Tangible ≠ только материальный предмет

GM использует Tangible Waste как противопоставление абстрактному мышлению: потери должны быть конкретно наблюдаемыми и идентифицируемыми.

### 4.4 Waste Type ≠ Cause

Для каждого типа GM даёт характеристики и Main Causes. Тип потери и причина её возникновения — разные категории.

### 4.5 Identification ≠ Elimination

Обнаружить потерю и устранить её — разные действия.

### 4.6 7 Types of Waste ≠ 5S

7 Types of Waste — классификация потерь.

5S / WPO — отдельная конструкция организации рабочего места, которая далее используется для их выявления и устранения.

### 4.7 Continuous Improvement ≠ реакция на единичную большую проблему

SOURCE прямо противопоставляет Reactive Improvement систематическому поиску множества малых возможностей. fileciteturn166file13

## 8. MECHANISM — МЕХАНИЗМ

### CANDIDATE — Waste Identification & Elimination

**Input:** конкретная выполняемая работа.

**Transformation:** различение Value Added / Non Value Added и выявление ненужных шагов.

**Output:** идентифицированная конкретная потеря.

**Следующее действие SOURCE:** устранение потери.

**Организационный эффект:** возможность перейти от абстрактного представления о потерях к конкретным малым возможностям улучшения.

**STATUS: CANDIDATE / SINGLE-SOURCE**

Важно: SOURCE в этой вагонетке не даёт полноценной пошаговой процедуры устранения каждой категории, поэтому механизм не расширяем.

## 14. CMOC INTERPRETATION

Здесь появляется важное для CMOC различение:

> **Потеря становится инженерным объектом улучшения тогда, когда её можно конкретно увидеть и идентифицировать в работе.**

И второе:

> **Непрерывное улучшение может строиться не только как реакция на крупное событие, а как систематическая работа с множеством малых конкретных возможностей.**
