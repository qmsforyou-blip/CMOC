# 01. DIS — различения

Главное правило:

> **DIS фиксирует границу, а не просто различие терминов.**

### Кандидаты, устойчиво прошедшие фильтр

|ID|Различение|Статус|
|---|---|---|
|ISO-D01|Контроль ≠ испытание|UPDATE / кандидат|
|ISO-D02|Переделка ≠ ремонт|UPDATE / кандидат|
|ISO-D03|Разрешение на отклонение ≠ разрешение на отступление|UPDATE / кандидат|
|ISO-D04|Обратная связь ≠ претензия|UPDATE / кандидат|
|ISO-D05|Улучшение ≠ поддержание достигнутого уровня|UPDATE / кандидат|
|ISO-D06|Постепенное улучшение ≠ прорывное улучшение|UPDATE / кандидат|
|ISO-D07|Объективное свидетельство ≠ решение|NEW-кандидат|
|ISO-D08|Среда ≠ процесс понимания среды|NEW-кандидат|
|ISO-D09|Заинтересованная сторона ≠ соответствующая заинтересованная сторона|NEW-кандидат|
|ISO-D10|Компетентность ≠ осведомлённость|NEW-кандидат|

**Важно:** это ещё **не номера LAB-002**.

# 04. CAP — способности

Здесь **особенно не спешим**.

В ISO термин «возможность» уже имеет собственное определение — способность объекта получить выход, соответствующий требованиям к этому выходу. Поэтому сам класс способности не выдуман нами.

Но **CMOC-CAP ещё не канон**.

Пока оставляем три кандидата:

### CAP-01

> Способность организации изменяться для адаптации к изменяющейся среде.

### CAP-02

> Способность СМК управлять взаимосвязанными процессами и ресурсами для получения результатов.

### CAP-03

> Способность процесса получать выход, соответствующий требованиям.

# 05. Что НЕ переносим

Это не менее важно, чем то, что переносим.

DROP

для:

- данные ≠ информация — как самостоятельного CMOC-DIS;
- процесс ≠ ресурс;
- ресурс ≠ поддержка;
- поставщик ≠ партнёр;
- краткосрочная цель ≠ долгосрочный фактор;
- качество ≠ отсутствие дефектов;
- улучшение ≠ изменение;
- улучшение ≠ инновация;
- стандарт ≠ модель совершенства.

Причина одна:

> **либо источник не формирует здесь устойчивой границы, либо различение тривиально для нашей задачи.**

И вот **это уже существенно важнее списка терминов**.

# 08. И вот здесь я бы поставил наш первый настоящий «патч ядра»

Не переносить пока весь `PATCH-ISO-9000-v1`.

А выделить **ядро повторений**:
CMOC-CANDIDATE-01
Среда → изменение / адаптация

CMOC-CANDIDATE-02
Цель → процесс → ресурс → результат

CMOC-CANDIDATE-03
Процесс ↔ процесс

CMOC-CANDIDATE-04
Свидетельство → анализ → решение → действие

CMOC-CANDIDATE-05
Потребность / ожидание → результат

CMOC-CANDIDATE-06
Результат → оценка → улучшение

CMOC-CANDIDATE-07
Ресурс → способность → действие → результат

**Вот эти семь кандидатов я бы сохранил как контрольные гипотезы CMOC.**

Не канон.

Не термины ISO.

И даже не «механизмы CMOC».

А именно:

> **структуры, которые ISO 9000 воспроизводит независимо в нескольких своих разделах.**
