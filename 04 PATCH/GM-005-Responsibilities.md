## 1. LOCATION

Ключевой фрагмент — **1.2 Fast Response, Responsibilities**, p. 13.

GM задаёт несколько уровней ответственности:

- Plant Manager или designated manufacturing lead — обеспечивает поддержание и эффективность Fast Response process;
- Plant Manager / designated manufacturing lead — назначает Champion и Co-Champion как facilitators;
- Site Leadership на Fast Response meeting — назначает leader (natural owner) для каждого concern/issue, если он ещё не назначен;
- Site Leadership — обеспечивает участие необходимых дисциплин;
- Site Leadership — определяет action и owner для RED items;
- Site Leadership — устанавливает следующую дату report out, если issue не закрыт.

Источник тем самым различает ответственность за **сам Fast Response process**, его **facilitation** и управление **конкретным Issue**.

## 3. DISTINCTIONS

### DIS-GM-005-01

**Process ownership ≠ facilitation.**

Plant Manager / designated manufacturing lead отвечает за то, чтобы Fast Response process maintained and effective. Champion / Co-Champion назначаются как facilitators.

```text
Process effectiveness
        ≠
Process facilitation
```

### DIS-GM-005-02

**Facilitator ≠ Issue Owner.**

Champion / Co-Champion фасилитируют Fast Response; Natural Owner назначается для конкретного concern/issue.

```text
Fast Response facilitation
        ≠
Ownership of specific issue
```

### DIS-GM-005-03

**Natural Owner привязан к конкретному concern/issue.**

GM требует назначать leader (natural owner) для каждого concern/issue, если он не был назначен ранее.

### DIS-GM-005-04

**Issue Owner ≠ все исполнители решения.**

В рамках Fast Response owner отвечает за problem solving / progress, при этом GM предусматривает поддержку всех необходимых disciplines и cross-functional team reviews.

### DIS-GM-005-05

**Site Leadership ≠ Support Functions.**

Site Leadership обеспечивает proper support from all disciplines through attendance. Функциональная поддержка является отдельным элементом организационной конструкции.

### DIS-GM-005-06

**RED ≠ просто статус.**

Для RED item GM требует определить action и owner.

### DIS-GM-005-07

**Open Issue ≠ Issue без следующего контрольного момента.**

Если issue не закрыт, должна быть установлена следующая дата report out.

## 8. PASSPORT

### Candidate Entity — Responsibility Allocation

**Name:** Responsibility Allocation  
**Type:** CANDIDATE / SINGLE-SOURCE  
**Source role:** распределение ответственности между уровнями процесса Fast Response и конкретным Issue.

### Source-defined boundary

**Process level:** Fast Response должен оставаться maintained and effective.  
**Facilitation level:** Champion / Co-Champion.  
**Issue level:** Natural Owner.  
**Support level:** необходимые disciplines.  
**Action level:** action + owner для RED.  
**Time-control level:** next report out date для незакрытого issue.

## 10. MECHANISM

### CANDIDATE — Responsibility Allocation Mechanism

Источник задаёт воспроизводимую последовательность действий:

1. есть concern / issue;
2. на Fast Response meeting определяется Natural Owner, если он отсутствует;
3. обеспечивается участие необходимых disciplines;
4. для RED определяется требуемое action и его owner;
5. если issue не закрыт, задаётся следующий report out date.

Это уже не просто наличие атрибута `Responsible`.

Здесь ответственность **назначается в отношении конкретного объекта и связывается с действием и временем последующего контроля**.

## 13. MACHINE

### CANDIDATE MACHINE — Responsibility Allocation

Инженерный тест:

```text
INPUT
Concern / Issue без явно заданного owner
        ↓
OPERATION / TRANSFORMATION
Назначение Natural Owner
+ обеспечение функциональной поддержки
+ назначение Action Owner для RED
+ назначение Next Report Out Date
        ↓
OUTPUT
Issue с явным ownership,
поддержкой, action и контрольной датой
        ↓
ORGANIZATIONAL EFFECT
Issue не остаётся организационно ownerless
```

### Ограничение

Источник подтверждает отдельные операции назначения, поддержки, action и timing, но не описывает самостоятельную универсальную процедуру `Responsibility Allocation` как термин.

Поэтому:

**MACHINE = CANDIDATE / SINGLE-SOURCE**

а не CANON.

## 17. CMOC INTERPRETATION

Главное добытое различение:

> **Ответственность в GM — не просто атрибут должности. Для конкретного Issue она назначается как организационная операция, связывающая объект с Natural Owner, необходимой поддержкой, действием и следующим контрольным моментом.**

Это даёт сильного кандидата для Атласа Машинок:

```text
OWNERLESS ISSUE
      ↓
[RESPONSIBILITY ALLOCATION]
      ↓
OWNED ISSUE
      +
SUPPORT
      +
ACTION
      +
NEXT CONTROL POINT
```

При этом не следует преждевременно утверждать, что вся ролевая архитектура GM является одной машиной. Более точное чтение Источника сейчас такое:

```text
Fast Response
├── Process governance
├── Facilitation
├── Responsibility Allocation
├── Functional Support
├── Issue Management
└── Time / Report-Out Control
```

**Responsibility Allocation остаётся CANDIDATE MACHINE / SINGLE-SOURCE.**
