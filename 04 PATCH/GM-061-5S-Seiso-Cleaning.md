## 1. SOURCE

SOURCE определяет третий шаг 5S — **Seiso / Cleaning**.

Определение:

> **To become aware of and eliminate all unwanted dirt, dust, grime, paint, labels, tape, etc…**

Purpose:

> **To eliminate unsafe conditions, improve quality of our products, enhance the workplace environment, identify and correct equipment problems (cleaning is checking), and initiate corrective action to prevent future accumulation of unwanted materials.** fileciteturn175file2

SOURCE тем самым связывает Cleaning не только с чистотой как состоянием, но и с **осознанным обнаружением проблем оборудования**.

Особенно важна формулировка:

> **cleaning is checking**

и последующая связь:

```text
IDENTIFY EQUIPMENT PROBLEM
→ CORRECT
→ INITIATE CORRECTIVE ACTION
→ PREVENT FUTURE ACCUMULATION
```

Последовательность выше частично реконструирована из SOURCE Purpose и не должна считаться дословной полной процедурой.

## 4. DISTINCTIONS — РАЗЛИЧЕНИЯ

### Cleaning ≠ просто удаление грязи

SOURCE связывает Cleaning с выявлением equipment problems. Поэтому Seiso имеет диагностический аспект.

### Cleanliness ≠ Equipment Condition

Чистое состояние и техническое состояние оборудования — разные объекты. Cleaning позволяет выявлять проблемы оборудования, но не является самим ремонтом оборудования.

### Identify ≠ Correct

SOURCE отдельно называет identification и correction.

### Correct ≠ Corrective Action

Особенно важно сохранить различение:

```text
IDENTIFY EQUIPMENT PROBLEM
→ CORRECT
→ CORRECTIVE ACTION
```

SOURCE не позволяет отождествлять эти действия.

### Corrective Action ≠ Cleaning

Corrective Action инициируется как последующая реакция для предотвращения будущего накопления unwanted materials; она не равна самой очистке.

### Cleaning ≠ Preventive Action

SOURCE говорит об initiate corrective action to prevent future accumulation. Не заменяем термин SOURCE более общим preventive action.

## 8. MECHANISM — МЕХАНИЗМ

### CANDIDATE — Cleaning-as-Checking

**Input:** рабочая зона / оборудование с загрязнениями и нежелательными материалами.

**Transformation:** очистка с одновременным визуальным/непосредственным выявлением состояния оборудования.

**Output:** очищенное рабочее место + выявленные equipment problems.

**Организационный эффект:** возможность своевременно исправить обнаруженные проблемы.

**STATUS: CANDIDATE / SINGLE-SOURCE**

Это более сильный механизм, чем просто «убрать грязь», потому что SOURCE прямо определяет **cleaning is checking**.

### CANDIDATE — Corrective Action Against Recurrence of Accumulation

SOURCE требует initiate corrective action для предотвращения будущего накопления unwanted materials.

**STATUS: CANDIDATE / SINGLE-SOURCE**

## 10. CORE CANDIDATE

> **Cleaning-as-Checking — организационная конструкция, в которой очистка рабочего места одновременно используется для выявления проблем оборудования, после чего обнаруженные проблемы корректируются и при необходимости запускается corrective action для предотвращения повторного накопления нежелательных материалов.**

**STATUS: CANDIDATE / SINGLE-SOURCE**

## 11. MACHINE — МАШИНКА

### CANDIDATE MACHINE — Cleaning-as-Checking

```text
INPUT
Workplace / Equipment State
+ Unwanted Materials
        ↓
[ CLEANING + CHECKING ]
        ↓
OUTPUT
Cleaned Workplace
+
Identified Equipment Problem
        ↓
[ CORRECT ]
        ↓
CORRECTED EQUIPMENT CONDITION
```

Инженерный тест:

- **INPUT:** рабочая зона / оборудование и unwanted materials;
- **OPERATION:** Cleaning, одновременно выполняемая как checking;
- **OUTPUT:** очищенная зона и/или выявленная проблема оборудования;
- **ORGANIZATIONAL EFFECT:** обнаруженная проблема получает возможность коррекции.

**MACHINE = CANDIDATE / SINGLE-SOURCE**

### Отдельная Machine для Corrective Action — пока NONE

SOURCE здесь говорит об initiate corrective action, но не раскрывает достаточный внутренний алгоритм этой corrective action. Поэтому не строим из этого самостоятельную машинку.

## 14. CMOC INTERPRETATION

GM-059 показала:

```text
PURPOSE
→ NECESSITY
→ REMOVE
```

GM-060:

```text
REQUIRED ITEM
→ BEST LOCATION
→ ACCESSIBILITY
```

GM-061 добавляет принципиально иной тип преобразования:

```text
CLEANING
→ CHECKING
→ CONDITION BECOMES KNOWABLE
```

То есть действие по изменению состояния среды одновременно становится **операцией получения информации о состоянии объекта**.

CMOC INTERPRETATION:

> **Некоторые физические операции могут одновременно изменять состояние объекта и повышать наблюдаемость его скрытого состояния.**

Это не SOURCE claim.

Ещё одна потенциально важная формула:

```text
ACTION ON ENVIRONMENT
        ↓
INFORMATION ABOUT OBJECT
        ↓
CORRECTION
        ↓
CORRECTIVE ACTION
```

Здесь особенно важно различать **коррекцию обнаруженной проблемы** и **корректирующее действие против будущего повторения/накопления**. SOURCE сам использует разные термины.
