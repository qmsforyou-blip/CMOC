# GM-067 — S-3: SHINE / Cleaning Instructions, Frequency & Organization

**Извещение на изменение:** 0176+280826  
**Источник:** GM Quality System Basics rev. March 2009  
**Раздел:** 5 S Workplace Organization / S-3: SHINE  
**Статус:** CANDIDATE / SINGLE-SOURCE

## 1. SOURCE

GM-067 рассматривает продолжение S-3: SHINE, относящееся не к устранению источника загрязнения как такового, а к организации самой операции очистки.

SOURCE устанавливает три конкретных требования:

- **Develop instructions for cleaning methods and frequency.**
- **Organize for cleaning (correct materials, rags, brooms, etc.).**
- **Find ways to reduce the time required for cleaning.**

Контекст S-3 также включает очистку machines, tools, floors, cabinets и требование, чтобы out-of-standard conditions могли быть легко идентифицированы и исправлены. fileciteturn184file0

## 4. DISTINCTIONS — РАЗЛИЧЕНИЯ

### Cleaning ≠ Cleaning Instruction

Очистка — выполняемое действие. Инструкция определяет, как это действие должно выполняться.

### Method ≠ Frequency

```text
METHOD
→ HOW?

FREQUENCY
→ HOW OFTEN?
```

SOURCE требует оба параметра.

### Instruction ≠ Material

Инструкция определяет способ действия; correct materials обеспечивают возможность его выполнения.

### Organize for Cleaning ≠ Clean

Организация условий выполнения очистки не тождественна самой очистке.

### Reduce Time ≠ Increase Speed

SOURCE требует **find ways to reduce the time required**, но не предписывает конкретный способ сокращения времени.

### Standardized Cleaning ≠ Standardization of Entire Workplace

Здесь речь идёт об организации операции очистки внутри S-3. Более широкая конструкция S-4 Standardize рассматривается отдельно.

## 6. EXTRACTION — ИЗВЛЕЧЕНИЕ

SOURCE позволяет выделить конструкцию:

```text
CLEANING OPERATION
        ↓
DEFINE
├─ METHOD
└─ FREQUENCY
        ↓
ORGANIZE RESOURCES
├─ RAGS
├─ BROOMS
└─ OTHER CORRECT MATERIALS
        ↓
CLEANING OPERATION
        ↓
SEARCH FOR TIME REDUCTION
```

Это не утверждение, что SOURCE задаёт именно такую последовательность. Это инженерная реконструкция содержания перечисленных требований.

## 7. REL — ОТНОШЕНИЯ

SOURCE поддерживает:

```text
Cleaning
→ Instructions
→ Method + Frequency
```

```text
Cleaning
→ Correct Materials
```

```text
Cleaning Operation
→ Time Required
→ Search for Reduction
```

SOURCE не устанавливает конкретную последовательность между этими элементами.

## 8. MECHANISM — МЕХАНИЗМ

### CANDIDATE — Cleaning Operation Definition

**Input:** необходимость выполнения очистки.

**Transformation:** определение method и frequency.

**Output:** заданный способ и периодичность очистки.

**Организационный эффект:** операция очистки получает определённую воспроизводимую рамку.

**STATUS: CANDIDATE / SINGLE-SOURCE**

### CANDIDATE — Cleaning Resource Organization

**Input:** определённая потребность в очистке.

**Transformation:** организация correct materials для очистки.

**Output:** средства очистки организованы для выполнения операции.

**STATUS: CANDIDATE / SINGLE-SOURCE**

### CANDIDATE — Cleaning Time Reduction Search

**Input:** существующая операция очистки.

**Transformation:** поиск способов сокращения требуемого времени.

**Output:** найденная возможность сокращения времени.

**STATUS: CANDIDATE / SINGLE-SOURCE — WEAK**

SOURCE не описывает конкретный алгоритм такого поиска.

## 9. CAPABILITY — СПОСОБНОСТИ

### CANDIDATE — Задавать воспроизводимый способ очистки

Способность определить method и frequency для cleaning operation.

**STATUS: CANDIDATE / SINGLE-SOURCE**

### CANDIDATE — Обеспечивать очистку необходимыми средствами

Способность организовать correct materials для выполнения очистки.

**STATUS: CANDIDATE / SINGLE-SOURCE**

### CANDIDATE — Искать сокращение времени операции

Способность систематически искать способы уменьшения времени, требуемого для очистки.

**STATUS: CANDIDATE / SINGLE-SOURCE — WEAK**

## 10. CORE CANDIDATE

> **Cleaning Operation Definition — конструкция задания метода и периодичности очистки, дополненная организацией необходимых средств для её выполнения и поиском возможностей сокращения требуемого времени.**

**STATUS: CANDIDATE / SINGLE-SOURCE**

## 11. MACHINE — МАШИНКА

### CANDIDATE MACHINE — Cleaning Operation Standardization

```text
INPUT
Cleaning Need
        ↓
[ DEFINE METHOD ]
        +
[ DEFINE FREQUENCY ]
        ↓
[ ORGANIZE CORRECT MATERIALS ]
        ↓
OUTPUT
Defined + Resourced

        ↓

```

**MACHINE = CANDIDATE / SINGLE-SOURCE**

Здесь машинка слабее Seiri/Seiton: SOURCE задаёт требуемые элементы конструкции, но не показывает полный цикл её разработки и проверки.

### Cleaning Time Reduction

**MACHINE = NONE / WEAK CANDIDATE**.

Есть направление действия, но нет достаточного операционного описания.

## 14. CMOC INTERPRETATION

GM-061 дала:

```text
CLEANING
→ CHECKING
→ EQUIPMENT PROBLEM
```

GM-066:

```text
DIRT / LEAK
→ SOURCE
→ ELIMINATE SOURCE
```

GM-067 добавляет ещё один уровень:

```text
CLEANING
→ METHOD
→ FREQUENCY
→ RESOURCES
```

Отсюда CMOC-гипотеза:

> **Для воспроизводимости организационной операции недостаточно определить само действие; необходимо задать как минимум способ его выполнения, периодичность и необходимые ресурсы.**

Это **CMOC INTERPRETATION**, не SOURCE claim.

Вторая гипотеза:

> **Организационная операция может рассматриваться как объект улучшения сама по себе: после задания её конструкции система должна искать способы уменьшения требуемого времени.**

Также **CMOC INTERPRETATION**.
