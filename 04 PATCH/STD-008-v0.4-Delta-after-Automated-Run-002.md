# STD-008-v0.4 — Delta after AUTOMATED-RUN-002

## Основание

Полный AUTOMATED RUN M01–M08 на SOURCE SRC-002 (GM Quality System Basics Overview — Supplier Audit), 18-09-2026.

## 1. Что подтверждено

Автоматический прогон подтвердил выполнение производственной цепочки без ручного конструирования промежуточных результатов:

`SOURCE → EXTRACTION → DISTINCTIONS → FORMULATIONS → NOMENCLATURE → CLASSIFICATION → PASSPORT → RELATIONS → CANONIZATION`

На каждом модуле зафиксирован явный результат и сохранена трассировка.

Контрольные результаты:

- M01: 100 EX;
- M02: 100 DIS;
- M03: 300 FORM;
- M04: 100 NOM;
- M05: 100 CLS;
- M06: 100 PAS;
- M07: 100 явных NO_RELATION, 0 relation candidates;
- M08: 100 decisions, 100 PROVISIONAL, 0 NEEDS_EVIDENCE, 0 CANONICAL.

## 2. Что подтверждено впервые

Подтвержден интерфейс сменного SOURCE в автоматическом режиме: фиксированная машина была применена к SRC-002 без изменения её нормативной семантики.

Подтверждена передача промежуточных результатов M01→M02→…→M08 в автоматическом прогоне.

## 3. Ограничение M07

Для M07 входом были изолированные паспорта. При таком представлении нельзя надёжно установить второй endpoint отношения без привлечения внешнего знания или более широкого source context.

Поэтому M07 корректно вернул явный отрицательный результат.

Это одновременно выявляет требование к будущему контракту M07: relation extraction должен получать source-supported multi-object context либо эквивалентный пакет оснований, если такой контекст нужен для установления endpoint'ов.

## 4. Ограничение M08

В AUTOMATED-RUN-002 M08 применил DECISION RULE к паспортам и не использовал relation candidates как самостоятельное основание.

Это допустимо как текущий контроль decision rule для объектов, но не является полным тестом ветви `Passport + Relation → Canonization Decision`.

Следовательно, полный automated run подтверждает object-decision branch M08, но relation-dependent branch M08 требует отдельного контрольного прогона.

## 5. Ограничение семантической проверки

AUTOMATED RUN подтверждает исполнение зафиксированной технологии и её интерфейсную управляемость. Он не доказывает автоматически семантическую адекватность каждого производного объекта исходному тексту.

Для этого сохраняются source trace, reverse trace, human/QC review и отдельные контрольные прогоны.

## 6. Правило обновления

Следующий автоматический тест не должен переписывать результаты AUTOMATED-RUN-002.

Он должен отдельно проверить:

1. M07 на multi-object source context;
2. передачу relation candidates в M08;
3. M08 решение с учётом relation evidence;
4. сохранение decision rule;
5. reverse trace до SOURCE.

## 7. Вывод

AUTOMATED-RUN-002 закрывает базовый интерфейсный automated run M01–M08, но не закрывает relation-dependent ветвь M08.

Формула:

> Автоматизация доказана как исполнение конвейера; семантическая полнота и relation-dependent canonization требуют отдельных испытаний.
