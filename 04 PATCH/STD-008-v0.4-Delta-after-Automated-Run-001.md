# STD-008 v0.4 — Delta after AUTOMATED-RUN-001

v0.3 + полный AUTOMATED-RUN-001 M01–M08 на реальном источнике.

Контролируемый прогон:
**40 → 40 → 120 → 40 → 40 → 40 → 25 → M08 decisions**

## 1. AUTOMATED RUN — НОВЫЙ ПОДТВЕРЖДЁННЫЙ КОНТРОЛЬ

Полный автоматический контур M01–M08 выполнен.

Подтверждено:

- последовательность фиксированных этапов;
- контрактные переходы между этапами;
- контроль кардинальности;
- сквозная трассировка;
- контроль границ этапов;
- явная фиксация `NEEDS_EVIDENCE`;
- отсутствие автоматической канонизации из одного источника.

## 2. ДЕФЕКТ В AUTOMATED RUN

На первом автоматическом исполнении M03 был обнаружен выход за границу этапа: в формулировки попало поле `CLASSIFICATION_HINT`.

Результат первого M03 не переписывался.

Был создан отдельный QC PATCH, после чего выполнен RE-RUN-001.

RE-RUN-001 прошёл QC.

Нормативный паттерн:

**RUN → QC → DEFECT → PATCH → RE-RUN → ACCEPT**

Обнаружение дефекта рассматривается как штатная функция контролируемой технологии, а не как основание скрытого исправления результата.

## 3. РАЗВЕДЕНИЕ ТРЁХ ДОКАЗАТЕЛЬСТВ

### 3.1 FULL SEQUENTIAL TEST

Показывает, что технология может быть выполнена последовательно по фиксированным операциям с контролируемыми переходами.

### 3.2 REPEATABILITY RUN

Показывает сопоставимость результатов повторного аналитического прогона при тех же правилах.

Ограничение: это не статистически независимый эксперимент с независимым исполнителем/моделью.

### 3.3 AUTOMATED RUN

Показывает, что зафиксированные контракты могут быть исполнены машиной без ручного конструирования промежуточных результатов.

Эти три свойства не следует объединять в одно утверждение.

## 4. ГРАНИЦА АВТОМАТИЗАЦИИ

MACHINE-SOURCE-001 автоматизирует производство **прослеживаемого source-bound результата**.

Это не означает:

- автоматическую универсализацию;
- автоматическую канонизацию CMOC;
- доказанную работу с любым классом источников;
- статистически доказанную независимую воспроизводимость.

Формула:

> **Автоматическое производство прослеживаемого результата ≠ автоматическая канонизация CMOC.**

## 5. QC PROTOCOL ДЛЯ AUTOMATED RUN

Каждый автоматический прогон должен проверяться минимум по следующим воротам:

1. **INTERFACE** — входной SOURCE_PACKAGE соответствует контракту.
2. **HANDOFF** — выход этапа принимается следующим этапом без ручной реконструкции.
3. **CARDINALITY** — заявленная кардинальность соблюдена.
4. **TRACE** — каждый результат имеет обратную трассировку до SOURCE.
5. **BOUNDARY** — этап не производит артефакты следующего уровня.
6. **STATUS** — неопределённость и исключения имеют явный статус.
7. **DECISION RULE** — M08 применяет зафиксированное правило, а не скрытую эвристику.
8. **HISTORY** — дефект не исправляется переписыванием исторического результата.
