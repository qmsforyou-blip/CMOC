## 1. SOURCE

После определения систематического подхода к Workplace Organization SOURCE вводит отдельный визуальный блок **FIRST IMPRESSIONS**.

Стр. 127 содержит формулу:

> “You never get a second chance to create a first impression.”

Стр. 128 предъявляет конкретную точку наблюдения:

> **FIRST IMPRESSION: MAIN ENTRANCE TO PLANT**

> **What is your first impression of this facility?**

Стр. 129 переносит ту же оптику на:

> **FIRST IMPRESSION: PLANT MAIN AISLE**

SOURCE не даёт на этих страницах формального чек-листа критериев оценки и не формулирует процедуру принятия решения по результату впечатления. fileciteturn171file0turn171file10

Поэтому фотографии/визуальные примеры рассматриваем прежде всего как **предъявление реального состояния рабочей среды**, а не как доказанный алгоритм аудита.

## 4. DISTINCTIONS — РАЗЛИЧЕНИЯ

### First Impression ≠ Formal Audit

SOURCE предлагает вопрос **“What is your first impression?”**, но не даёт здесь критериев аудита или scoring.

### Visual Evidence ≠ доказательство соответствия

Фотография показывает состояние, но сама по себе не устанавливает соответствие конкретному требованию.

### Observation ≠ Evaluation

Наблюдать состояние можно без вынесения формальной оценки. SOURCE этих двух действий здесь не объединяет.

### First Impression ≠ весь Workplace Organization

First Impression — отдельная визуальная оптика внутри раздела WPO, а не определение WPO.

### Main Entrance ≠ Production Process

Главный вход выбран как точка первого впечатления; SOURCE не утверждает, что это производственный контрольный пункт.

### Main Aisle ≠ VS

Главный проход не является Verification Station.

Это именно **визуальная предъявляемость состояния**, а не установленный SOURCE алгоритм оценки.

```text

```

Такую цепочку не добавляем.

## 8. MECHANISM — МЕХАНИЗМ

### NONE / WEAK CANDIDATE — First Impression

SOURCE показывает точку наблюдения и задаёт вопрос наблюдателю, но не раскрывает воспроизводимую операцию преобразования входа в формальный результат.

Поэтому:

**MECHANISM = NONE**

Для будущей проверки можно сохранить слабую гипотезу:

> визуальное предъявление состояния рабочей среды может служить быстрым способом обнаружения очевидных отклонений.

Но это пока **CMOC INTERPRETATION**, а не SOURCE mechanism.

## 9. CAPABILITY — СПОСОБНОСТЬ

### CANDIDATE — Быстро воспринимать состояние рабочей среды

SOURCE позволяет предположить способность организации предъявлять ключевые зоны предприятия так, чтобы наблюдатель мог сформировать непосредственное впечатление о состоянии среды.

**STATUS: CANDIDATE / SINGLE-SOURCE**

Однако это слабый кандидат, потому что SOURCE не формализует критерии или результат.

## 10. CORE CANDIDATE

### CANDIDATE — First-Impression Observation Point

> **First-Impression Observation Point — выделенная физическая точка рабочей среды, через которую состояние предприятия предъявляется непосредственному визуальному наблюдению.**

**STATUS: CANDIDATE / SINGLE-SOURCE**

Важно: это не следует автоматически считать сущностью CMOC. Пока это кандидат, добытый из конкретной визуальной конструкции SOURCE.

## 11. MACHINE — МАШИНКА

**MACHINE = NONE**

Причина:

```text
INPUT
facility state

?

OPERATION
?

OUTPUT
first impression
```

SOURCE показывает Input и субъективный результат восприятия, но не задаёт воспроизводимую Transformation.

Следовательно, инженерный тест машинки **не пройден**.

Это принципиально: мы не превращаем красивую визуальную конструкцию в Machine только потому, что она полезна.

## 14. CMOC INTERPRETATION

GM-054 дала:

```text
WORKPLACE
→ VISIBLE STATE
→ NON-STANDARD CONDITION CAN BE SEEN
```

GM-057 дала:

```text
VISIBILITY
+
INSTRUCTION
+
REVIEW
+
MAINTENANCE
→ SUSTAINED STATE
```

GM-058 добавляет другую форму наблюдаемости:

```text
KEY PHYSICAL LOCATION
        ↓
DIRECT OBSERVATION
        ↓
IMMEDIATE PERCEPTION
```

Отсюда осторожная CMOC-гипотеза:

> **Некоторые свойства организационной среды могут быть предъявлены непосредственно в физической реальности, без предварительного преобразования в запись или отчёт.**

Но непосредственное впечатление ещё не является управленческим решением.

Это важная граница:

```text
OBSERVATION
   ≠
EVALUATION
   ≠
DECISION
```
