# GM-096 — Workshop / Action-Plan Conversion — Cross-Check

**Date:** 30-08-2026
**Source:** GM Quality Systems Basics rev. March 2009, pp. 346–350
**Status:** SOURCE-DERIVED / CROSS-CHECK / NON-CANON

## 1. Question

Is **Workshop / Action-Plan Conversion** a new CMOC Machine, or is it an assembly/pattern over existing CMOC mechanisms?

## 2. Source-derived architecture

The GM Workshop material establishes a sequence in which cross-functional teams examine SHALL requirements, current status and gaps, develop proposals, define forms/tracking and management review, and transfer unfinished items into the QSB Action Plan.

Compact form:

`SHALL → Current Status → Gap → Proposal → Tracking/Form → Management Review → Action Plan → Implementation`

The Workshop therefore has a recognizable operational boundary, but its output is primarily an **Action Plan** and its operation combines several mechanisms already identified in CMOC.

## 3. Comparison with existing CMOC architecture

The current CMOC architecture already treats a gap as an object that requires:

`Problem/Gap → Decision → Action → Responsibility → Due Date → Status → Evidence → Closure`

It also distinguishes diagnosis from the subsequent implementation of corrective/development actions.

Therefore the GM Workshop does not justify creating a generic new Machine merely because it packages these activities as a Workshop.

## 4. What GM adds

GM provides a strong source example of an **action-oriented collective review mechanism**:

- requirements are reviewed by cross-functional participants;
- current status is made explicit;
- gaps are identified;
- proposed changes/actions are developed;
- management is involved;
- unfinished work is transferred into a tracked Action Plan.

The source therefore adds provenance and operational evidence for a CMOC pattern already present in diagnostic/development architecture.

## 5. Important distinction

### Workshop ≠ Training

The Workshop is not exhausted by knowledge transfer. Its explicit deliverable is connected to proposals, action items and the QSB Action Plan.

### Workshop ≠ Diagnosis

Diagnosis identifies current state and gap. The Workshop additionally converts the identified gap into a managed development path.

### Action Plan ≠ List of Problems

An Action Plan is a management object containing actions and ownership/tracking, not merely a register of deficiencies.

### Action Plan ≠ Implementation

The plan defines and tracks intended action. Actual implementation remains a subsequent event requiring evidence.

## 6. Machine decision

**Decision: NO NEW TOP-LEVEL MACHINE at this stage.**

The strongest interpretation is:

> **Workshop / Action-Plan Conversion is a composite mechanism / Assembly pattern that orchestrates existing CMOC mechanisms for collective transition from requirement/gap to managed development action.**

## 7. Possible Assembly

A future CMOC Assembly may use:

`Requirement Assessment + Gap Identification + Cross-functional Review + Decision + Action Planning + Responsibility + Tracking + Management Review`

The GM Workshop is useful as a source-derived realization of this Assembly.

## 8. Candidate Mechanisms involved

- Requirement Operationalization
- State Representation / Statusing
- Measurement/Verification where applicable
- Decision Gate where a decision is required
- Action-Plan Conversion
- Management Review
- Controlled Implementation
- Closure / Acceptance

No new Machine is required merely to package these mechanisms as a Workshop.

## 9. CMOC significance

The most valuable source-derived contribution is the explicit transition:

`DIAGNOSIS → DEVELOPMENT OBJECT → ACTION PLAN`

This strengthens the architecture of CMOC diagnostic products: a diagnostic output should not terminate at a finding/report; a material gap can become a managed development object with action, responsibility, tracking and review.

## 10. Candidate distinction for later Canon consideration

> **Identified Gap ≠ Managed Development Object**

A gap becomes a managed development object when it acquires an action, responsibility, tracking and a route to review/closure.

**Status:** candidate distinction, not yet canonical.
