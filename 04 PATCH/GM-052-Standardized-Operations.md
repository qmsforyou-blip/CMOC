## 4. DISTINCTIONS — РАЗЛИЧЕНИЯ

### 4.1 Standardized Operations ≠ Standardized Work

**Standardized Operations** — название более широкого раздела.

**Standardized Work** — один из его компонентов.

### 4.2 Standard Operation ≠ Operator Instructions

SOURCE разделяет:

- **Standard Operation** — Major Steps, Time, Materials, Work Flow;
- **Operator Instructions** — Job Element Details, What, How & Why. fileciteturn156file5

Не объединяем их в один документ/механизм без дальнейшего SOURCE.

### 4.3 Workplace Organization ≠ Standardized Work

5S/WPO создаёт организованное рабочее окружение; Standardized Work описывает выполнение работы.

### 4.4 Operator Instructions ≠ Training

JES содержит What/How/Why. Обучение оператора — отдельный элемент, который SOURCE раскрывает далее.

### 4.5 Manufacturing Gage Control ≠ Standardized Work

Это отдельный компонент Standardized Operations, связанный с квалификацией продукта по известным стандартам и спецификациям.

### 4.6 Clean workplace ≠ управляемость сама по себе

SOURCE на стр. 106 определяет WPO как clean, well-organized work environment, но сама по себе чистота не доказывает наличие полного механизма управления.

## 8. MECHANISM — МЕХАНИЗМ

### CANDIDATE — Standardized Work Structure

**Input:** выполняемая производственная работа.

**Transformation:** выделение Major Steps, Time, Materials и Work Flow; затем детализация Job Elements через What / How / Why.

**Output:** воспроизводимое представление того, как работа должна выполняться.

**Организационный эффект:** появляется единая основа для последующего выполнения и улучшения работы.

**STATUS: CANDIDATE / SINGLE-SOURCE**

Остальные компоненты раздела пока рассматриваем как элементы более широкой конструкции, а не как отдельные механизмы без дополнительного SOURCE.

## 11. MACHINE — МАШИНКА

На этом фрагменте **не следует преждевременно объявлять весь Standardized Operations одной машинкой**.

### CANDIDATE MACHINE — Standardized Work Definition

```text
INPUT
Work to be Performed
        ↓
[ DEFINE / STRUCTURE WORK ]
        ↓
Major Steps
+ Time
+ Materials
+ Work Flow
        ↓
[ DETAIL JOB ELEMENTS ]
        ↓
What + How + Why
        ↓
OUTPUT
Repeatable Work Definition
        ↓
EFFECT
Predictable Baseline for Improvement
```

Инженерный тест:

- **INPUT:** выполняемая работа;
- **OPERATION:** структурирование и детализация;
- **OUTPUT:** определённая воспроизводимая конструкция выполнения;
- **EFFECT:** repeatable / predictable baseline.

**MACHINE = CANDIDATE / SINGLE-SOURCE**

Но окончательно подтверждать Machine будем после изучения 4.4, где SOURCE раскрывает сам Standardized Work.

## 14. CMOC INTERPRETATION

GM-052 вводит важное различение между **работой как фактом** и **работой как воспроизводимой конструкцией**.

Без стандартизации:

```text
WORK
→ зависит от исполнителя
→ вариативность
```

В конструкции GM:

```text
WORK
→ MAJOR STEPS
→ TIME / MATERIALS / FLOW
→ JOB ELEMENTS
→ WHAT / HOW / WHY
→ REPEATABLE / PREDICTABLE BASELINE
```

CMOC-интерпретация:

> **Чтобы улучшать работу воспроизводимо, сначала необходимо иметь воспроизводимую основу, относительно которой изменение может быть различено.**

Это CMOC INTERPRETATION, не SOURCE claim.

Особенно интересно, что GM прямо связывает baseline с **continuous improvement** и одновременно включает оператора в initial и ongoing improvements. fileciteturn155file0
