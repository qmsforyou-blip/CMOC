# DECISION-AUTOMATION-001

## Статус
CONTRACT CANDIDATE — v0.1

## Назначение

Зафиксировать условия, при которых детерминированное утверждённое RULE может формировать окончательный DECISION без обязательного участия человека в каждом отдельном случае.

## Главный принцип

Если DECISION полностью выводится из:

- уже зафиксированного RECONCILIATION_RESULT;
- заранее утверждённого RULE;
- проверяемых условий этого RULE;

то такой DECISION может считаться полноценным DECISION, а не recommendation.

## Условия автоматического Decision

RULE может формировать окончательный DECISION только если одновременно выполнены условия:

1. RULE имеет уникальный идентификатор;
2. RULE заранее утверждено;
3. область применимости RULE определена;
4. входные условия RULE однозначно проверяемы;
5. результат RULE детерминирован;
6. RULE не выполняет скрытое новое сопоставление;
7. RULE не изменяет RECONCILIATION_RESULT;
8. Decision сохраняет идентификатор RULE;
9. Decision сохраняет traceability к входному результату;
10. Decision не выполняет физический CMOC admission.

## Первый разрешаемый класс

Наиболее простой кандидат для автоматизации:

EXISTING_EQUIVALENT
→ APPROVED RULE
→ ADMIT_EXISTING

Но даже эта цепочка требует заранее утверждённого RULE.

Без такого RULE:

EXISTING_EQUIVALENT
→ DECISION

не считается автоматическим выводом.

## ADMIT_NEW

ADMIT_NEW не автоматизируется по общему правилу только на основании:

- NO_MATCH;
- NEEDS_REVIEW;
- отсутствия найденного эквивалента.

Для автоматического ADMIT_NEW требуется отдельное утверждённое правило, которое явно определяет достаточное основание считать объект новым.

Пока такого правила нет, ADMIT_NEW требует HUMAN Decision.

## REJECT

Автоматический REJECT возможен только при наличии отдельного утверждённого RULE с явно определённым основанием отказа.

Отсутствие MATCH само по себе не является основанием REJECT.

## DEFER

DEFER может быть автоматизирован, если заранее утверждённое RULE однозначно устанавливает условие, при котором окончательное решение должно быть отложено.

## HUMAN

HUMAN может принимать окончательный DECISION независимо от наличия автоматического RULE, если соблюдены требования DECISION-RULES-001 и DECISION-AUTHORITY-001.

## MACHINE / LLM

MACHINE / LLM без утверждённого RULE формирует только recommendation.

Нельзя считать произвольный вывод LLM детерминированным RULE.

Допустимая цепочка:

MACHINE / LLM
→ recommendation
→ HUMAN
→ DECISION

или:

MACHINE / LLM
→ проверка утверждённого RULE
→ RULE
→ DECISION

## Traceability

Автоматический DECISION должен позволять восстановить:

- RECONCILIATION_RESULT;
- match_id;
- RULE ID;
- входные условия;
- полученный результат;
- время принятия;
- версию RULE.

## Boundary

Автоматизация Decision не расширяет права слоя Decision.

Она не разрешает:

- скрытое сопоставление;
- изменение Discovery;
- изменение Reconciliation;
- прямую запись в CMOC;
- автоматическое объявление NEEDS_REVIEW новым объектом.

Цепочка остаётся:

RECONCILIATION_RESULT
→ DECISION
→ ADMISSION
→ CMOC

## Архитектурный вывод

Для MVP:

- HUMAN — полноценный субъект DECISION;
- APPROVED RULE — полноценный субъект DECISION в пределах утверждённого правила;
- MACHINE / LLM — recommendation, если не действует как исполнитель утверждённого RULE;
- CMOC admission всегда остаётся отдельным шагом.
