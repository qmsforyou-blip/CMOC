# INV-003 — Инвариант управляемого исправления результата v0.1

## Формулировка

**NEEDS_EVIDENCE не исправляется молча.**

Если производственная машина останавливает результат со статусом `NEEDS_EVIDENCE`, дальнейшее движение возможно только через:

`NEEDS_EVIDENCE → EXPLICIT OPERATOR DECISION → NEW BATCH → RECHECK → DECISION`

## Правила

1. Исходная запись с `NEEDS_EVIDENCE` не переписывается.
2. Решение оператора фиксируется явно.
3. Повторная проверка выполняется как новый производственный проход.
4. Новый проход получает новый `BATCH_ID`.
5. Результат повторной проверки имеет собственное решение и трассировку.
6. Исправление не должно содержать скрытого использования внешнего знания.
7. `PROVISIONAL` не означает `CANONICAL`.
8. При недостаточном основании повторная проверка снова может завершиться `NEEDS_EVIDENCE` или `REJECT`.

## Минимальная форма

`RESULT(NEEDS_EVIDENCE) + OPERATOR_DECISION → NEW_BATCH → RECHECK → RESULT`

## Назначение

Инвариант отделяет:

- исходный результат машины;
- человеческое решение о дальнейшем действии;
- новый производственный проход;
- результат повторной проверки.

Тем самым исправление становится **аудируемой производственной операцией**, а не скрытым редактированием знания.

Проверено на SRC-002:

`M07 REL-001 → M08 CAN-001 NEEDS_EVIDENCE → explicit operator decision → M08 recheck → PROVISIONAL`

## Граница доказательства

Инвариант подтверждён на одном конкретном сценарии SRC-002 / M08 CAN-001. Универсальность для всех машин, TASK и типов исправлений этим проходом не утверждается.
