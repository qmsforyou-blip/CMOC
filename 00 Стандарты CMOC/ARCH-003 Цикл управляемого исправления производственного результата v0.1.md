# ARCH-003 — Цикл управляемого исправления производственного результата v0.1

## Назначение

ARCH-003 фиксирует архитектурный цикл для случая, когда производственная машина не может принять результат к дальнейшему движению без дополнительного основания.

## Контур

```
OUTPUT
  ↓
CONTRACT / QC
  ↓
ACCEPT ─────────────→ HANDOFF
  │
  ├→ REJECT
  │
  └→ NEEDS_EVIDENCE
          ↓
   EXPLICIT OPERATOR DECISION
          ↓
       NEW BATCH
          ↓
        RECHECK
          ↓
   ACCEPT / REJECT / NEEDS_EVIDENCE
```

## Связь с инвариантами

- INV-001 — разделяет MACHINE, SOURCE, TASK и BATCH.
- INV-002 — запрещает автоматическую приемку результата следующей машиной.
- INV-003 — требует явного решения и нового Batch при управляемом исправлении.

## Архитектурные правила

1. Результат машины является самостоятельным артефактом.
2. Проверка контракта и QC предшествуют HANDOFF.
3. `NEEDS_EVIDENCE` означает остановку производственного движения.
4. Операторское решение является отдельным событием, а не скрытой частью результата машины.
5. Повторная обработка выполняется новым производственным проходом.
6. Новый проход получает новый `BATCH_ID`.
7. Предыдущий результат сохраняется как историческая запись.
8. Результат RECHECK имеет собственную трассировку.
9. Повторная проверка не гарантирует ACCEPT: допустимы `ACCEPT`, `REJECT` и повторный `NEEDS_EVIDENCE`.
10. `PROVISIONAL` не означает CMOC `CANONICAL`.

## Evidence

Контур проверен на SRC-002:

`M07 REL-001 → M08 CAN-001 NEEDS_EVIDENCE → explicit operator decision → M08 recheck → PROVISIONAL`

Подтверждающие записи:

- `INV-003 Инвариант управляемого исправления результата v0.1.md`
- `CANONIZATION-DECISION-SRC-002-M08-002-CAN-001-RECHECK.md`
- `SUPERAGENT-RUN-011-SRC-002-M08-CAN-001-RECHECK.md`

## Граница доказательства

ARCH-003 подтверждён на одном сценарии исправления результата M08. Это не является доказательством универсальности цикла для всех TASK, машин и типов ошибок.

## Практический смысл

Суперагент не обязан «уметь исправлять» результат сам.

Он обязан:

`STOP → RECORD → REQUEST / ACCEPT EXPLICIT DECISION → CREATE NEW BATCH → RECHECK`

То есть управляемое исправление становится частью производственной архитектуры, а не исключением из неё.
