# INV-001 — Инвариант параметризованной производственной машины

**DATE:** 18-09-2026  
**STATUS:** EVIDENCE-BACKED v0.1  
**DOMAIN:** CMOC / Production Architecture

## 1. Инвариант

> **MACHINE ≠ SOURCE ≠ TASK ≠ BATCH**

Параметризованная производственная машина отделяет неизменяемое производственное ядро от материала обработки, производственной операции и конкретного прохода.

## 2. Определения

- **MACHINE** — фиксированное ядро производственных правил и операций.
- **SOURCE** — материал/пакет материала, поступающий на обработку.
- **TASK** — явно заданная производственная операция.
- **BATCH** — идентификатор конкретной реализации `SOURCE + TASK` в рамках одного производственного прохода.
- **OUTPUT** — явный продукт выполнения TASK.
- **HANDOFF** — явно зафиксированная передача OUTPUT предыдущего TASK как INPUT следующего TASK.

## 3. Правило

Машина не должна содержать SOURCE как скрытую часть своего ядра, TASK не должен определяться неявным состоянием предыдущего прохода, а предыдущий OUTPUT не должен использоваться без явной передачи.

Минимальная форма выполнения:

`INPUT + TASK + CONTRACT → BATCH → OUTPUT + TRACEABILITY`

## 4. Цепочка

При последовательной обработке:

`TASK₁ → TASK₂ → TASK₃`

переход должен иметь форму:

`OUTPUT₁ + declared handoff → INPUT₂`

Каждый TASK получает собственный BATCH_ID.

## 5. Evidence basis

Инвариант опирается на следующие контрольные прогоны:

- **CONTROL-RUN-007** — SRC-003 / M03, прямой SOURCE_PACKAGE.
- **CONTROL-RUN-008** — SRC-003 / M03, повторный контрольный прогон.
- **CONTROL-RUN-009** — SRC-002 / M03, смена SOURCE при неизменном MACHINE/PROMPT.
- **CONTROL-RUN-010** — SRC-002 / M02, смена TASK при неизменном SOURCE/MACHINE/PROMPT.
- **CONTROL-RUN-011** — SRC-002 / M01→M02→M03, явные handoff между TASK без скрытого состояния.

## 6. Что подтверждено

1. Один и тот же AGENT-SOURCE-001 может быть применён к разным SOURCE в протестированном M03-маршруте.
2. Один и тот же SOURCE может быть обработан разными TASK в протестированной паре M02/M03.
3. Один SOURCE/TASK pass получает отдельный BATCH_ID.
4. Промежуточный OUTPUT может передаваться следующему TASK как явно объявленный INPUT.
5. В протестированной цепочке M01→M02→M03 отсутствие скрытого состояния проверено явно.
6. Трассировка является частью производственного результата.

## 7. Граница доказательства

Инвариант пока не следует трактовать как доказательство универсальной применимости всех TASK ко всем SOURCE.

Не подтверждены данным набором тестов:

- универсальная прямопоточная обработка M04–M08;
- универсальная семантическая корректность результатов;
- автоматическая канонизация;
- отсутствие скрытого состояния во всех возможных реализациях и всех TASK;
- универсальность инварианта за пределами протестированной архитектуры.

## 8. Архитектурное следствие

Если инвариант соблюдается, суперагент может выступать оркестратором цепочки, не становясь носителем скрытого знания каждого предыдущего прохода.

Производственные машины остаются самостоятельными:

`Machine₁ → explicit OUTPUT₁ → Machine₂ → explicit OUTPUT₂ → Machine₃`

а оркестрация определяется контрактами и handoff, а не неявной памятью.

## 9. Формула CMOC

> **CMOC-машина должна быть параметризованной: её ядро фиксировано, SOURCE и TASK подаются явно, каждый проход получает BATCH, а результат следующей операции поступает только через явный HANDOFF.**
