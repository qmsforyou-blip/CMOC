# SPEC-002 — Интерфейс сменного Источника для AGENT-SOURCE-001

**Версия:** 0.4  
**Дата:** 18-09-2026  
**Назначение:** определить минимальный стандарт подключения любого нового Источника к `AGENT-SOURCE-001`.

---

## 1. Назначение

`AGENT-SOURCE-001` является стандартным сменным модулем обработки Источника.

`SPEC-002` определяет интерфейс между агентом и конкретным Источником.

Принцип:

> **Агент остаётся неизменным. Меняется только подключаемый SOURCE_PACKAGE и его идентификация.**

---

## 2. SOURCE_PACKAGE

Источник в CMOC рассматривается как **логическая единица содержания**, которая может быть представлена одним или несколькими файлами/носителями.

Пример:

```text
SOURCE_PACKAGE
├── PDF-001
├── PDF-002
├── JPEG-001
├── JPEG-002
└── ...
```

Форматы могут быть разными. Например: PDF, JPEG, PNG, XLSX и другие доступные носители.

Несколько файлов одного Источника не являются несколькими Источниками и сами по себе не создают несколько Batch.

---

## 3. Входной пакет Источника

Для запуска обработки агент получает:

```text
SOURCE_ID
SOURCE_NAME
SOURCE_TYPE
SOURCE_VERSION — если известна
SOURCE_PACKAGE
SOURCE_CONTEXT — если необходим
TASK — требуемый проход / этап
```

Минимально обязательны:

```text
SOURCE_ID
SOURCE_NAME
SOURCE_PACKAGE
```

---

## 4. SOURCE_ID

Каждый Источник должен иметь уникальный идентификатор.

Пример:

```text
SRC-GM-QSB-001
SRC-ISO-9001-2025-001
SRC-TOYOTA-001
```

Идентификатор Источника не изменяется при последующих проходах.

Новая редакция Источника не создаёт новый `SOURCE_ID`, если это тот же объект Источника; версия фиксируется отдельно.

---

## 5. SOURCE_NAME

Полное рабочее название Источника.

Пример:

```text
GM Quality System Basics Overview Supplier Audit
```

Название не является идентификатором и может уточняться без изменения `SOURCE_ID`.

---

## 6. SOURCE_PACKAGE

`SOURCE_PACKAGE` должен позволять установить состав входного материала.

Для каждого элемента пакета по возможности фиксируются:

```text
FILE_ID
FILE_NAME
FILE_TYPE
FILE_ORDER — если имеет значение
FILE_ROLE — если известна
```

`FILE_ROLE` может указывать, например, что файл содержит основной текст, приложение, изображение, таблицу или продолжение другого материала.

Если взаимосвязи между файлами неизвестны, агент не должен выдумывать их. Он фиксирует неопределённость.

---

## 7. Проверка целостности SOURCE_PACKAGE

До начала содержательной обработки агент обязан:

1. установить состав пакета;
2. проверить доступность заявленных файлов;
3. определить очевидные связи между файлами;
4. выявить отсутствующие или недоступные части;
5. зафиксировать состояние целостности пакета.

Минимальные состояния:

```text
COMPLETE
PARTIAL
UNKNOWN
```

`PARTIAL` означает, что часть заявленного Источника отсутствует или недоступна.

При `PARTIAL` агент может обрабатывать доступный материал, но обязан явно указать ограничение в результате и не выдавать его за обработку полного Источника.

---

## 8. SOURCE_VERSION

Если версия, редакция, дата или иная идентификация носителя известна, она фиксируется.

Если она неизвестна:

```text
UNKNOWN
```

Агент не должен самостоятельно выдумывать версию.

---

## 9. SOURCE_CONTEXT

Необязательное поле.

Может содержать:

- сведения о происхождении Источника;
- назначение обработки;
- уже выполненные проходы;
- ограничения;
- связанные объекты CMOC.

Контекст не заменяет содержание Источника.

---

## 10. TASK

Задание определяет текущую производственную операцию.

Примеры:

```text
EXTRACTION
DISTINCTIONS
FORMULATIONS
NOMENCLATURE
CLASSIFICATION
PASSPORT
RELATIONS
CANONIZATION
```

Если задача не указана, агент не должен самостоятельно выбирать следующий этап как факт. Он должен запросить или предложить этап.

## 10A. TASK как сменный параметр интерфейса

`TASK` является самостоятельным входным параметром интерфейса. Один и тот же `SOURCE_PACKAGE` может запускаться с разными `TASK` без изменения фиксированного ядра агента. Для нового прохода создаётся новый `BATCH_ID`. Входом может быть непосредственно `SOURCE_PACKAGE` либо результат предыдущего прохода, если это предусмотрено контрактом TASK; предыдущий результат не должен использоваться молча.

Проверено на SRC-003: `TASK=EXTRACTION`, `TASK=DISTINCTIONS`, `TASK=FORMULATIONS` непосредственно от `SOURCE_PACKAGE`.

В пределах проверенной границы `TASK` и `SOURCE_PACKAGE` являются независимыми измерениями сменности интерфейса. Это подтверждает интерфейсную возможность прямого входа для M01–M03, но не универсальную допустимость прямого входа для остальных TASK.

## 10B. Прямой TASK

Если конкретный TASK допускает прямой вход из `SOURCE_PACKAGE`, агент может выполнить его без производства и потребления промежуточных результатов предыдущих TASK.

Обязательны: `SOURCE_ID`, `BATCH_ID`, `TASK`, `SOURCE_PACKAGE_STATUS`, `TRACEABILITY`, `STATUS`.

Прямой TASK не отменяет требований source-only, прослеживаемости, неопределённости и запретов на скрытый синтез.

---

## 11. Производственная единица

Каждый запуск обработки Источника получает собственный идентификатор Batch.

```text
BATCH_ID
```

Рекомендуемый формат:

```text
BATCH-SRC-GM-QSB-001-001
```

Один Batch относится к одному Источнику и одному определённому производственному проходу.

Несколько файлов внутри одного `SOURCE_PACKAGE` не создают несколько Batch.

---

## 12. Прослеживаемость

Минимальная цепочка:

```text
SOURCE_ID
    ↓
SOURCE_PACKAGE
    ↓
BATCH_ID
    ↓
PASS
    ↓
OUTPUT
```

Для каждого произведённого результата должна сохраняться возможность установить, из какого Источника, какого файла и какого прохода он получен, если такая детализация доступна.

---

## 13. Запреты интерфейса

Подключение нового Источника не даёт агенту права:

- изменять стандарт `AGENT-SOURCE-001`;
- изменять CMOC Core;
- смешивать несколько Источников в один Batch;
- выдавать синтез за извлечение;
- скрывать отсутствие данных;
- выдумывать отсутствующие сведения;
- самостоятельно канонизировать результат, если это не является текущим заданием;
- игнорировать доступные части `SOURCE_PACKAGE`, относящиеся к текущему проходу.

---

## 14. Выход интерфейса

После выполнения операции агент обязан вернуть структурированный результат, содержащий минимум:

```text
SOURCE_ID
BATCH_ID
TASK
STATUS
SOURCE_PACKAGE_STATUS
OUTPUT
TRACEABILITY
OPEN_QUESTIONS — если есть
```

---

## 15. Критерий корректного подключения

Источник считается корректно подключённым, если агент может однозначно ответить:

1. Что это за Источник?
2. Какой его идентификатор?
3. Из каких доступных частей состоит `SOURCE_PACKAGE`?
4. Полон ли пакет или есть ограничения?
5. Какой Batch создан?
6. Какой проход выполняется?
7. Что является результатом прохода?
8. Как результат связан с исходным Источником и его частями?

---

## 16. Архитектурный принцип

```text
              AGENT-SOURCE-001
                     │
          ┌──────────┼──────────┐
          ↓          ↓          ↓
        SRC-A      SRC-B      SRC-C
          │          │          │
      PACKAGE     PACKAGE     PACKAGE
      ┌──┼──┐        │       ┌──┼──┐
     PDF JPG XLS     PDF     PDF JPG PNG
       │     │        │        │     │
     Batch  Batch?    Batch   Batch  Batch?
```

**Уточнение:** внутри каждого `SOURCE_PACKAGE` все файлы одного Источника обслуживаются **одним Batch на конкретный производственный проход**. Схема выше показывает состав пакетов, а не дополнительные Batch для файлов.

Итого:

```text
AGENT-SOURCE-001 — производственная машина
SOURCE_PACKAGE  — сменный комплект Источника
BATCH           — производственная партия прохода
```

---

## 17. Первый режим внедрения

Версия 0.2 предназначена для испытания на уже обработанном Источнике `GM Quality System Basics Overview Supplier Audit`, представленном комплектом взаимодополняющих PDF и JPEG.

Критерий испытания:

> агент должен воспроизводимо выполнить заданный проход без знания, встроенного специально под GM QSB, и корректно обработать комплект как единый `SOURCE_PACKAGE`.

После успешного испытания тот же интерфейс подключается к новому Источнику без изменения базовой технологии.
