# STD-0001. Универсальный объект CMOC

**Версия:** 0.1  
**Статус:** Действует

---

# 1. Назначение

Настоящий стандарт определяет минимальную структуру объекта CMOC.

Все объекты CMOC создаются, хранятся и развиваются в соответствии с данным стандартом.

Стандарт является базовым для всей системы CMOC.

---

# 2. Область действия

Настоящий стандарт обязателен для всех объектов, регистрируемых в CMOC.

Исключения не допускаются.

---

# 3. Основные принципы

## 3.1. Объект первичен

Объект CMOC существует независимо от способа хранения.

Markdown является одной из возможных форм хранения объекта.

---

## 3.2. Регистрация обязательна

Любой объект после возникновения подлежит регистрации.

Объекты без идентификатора в CMOC не существуют.

---

## 3.3. Минимальный паспорт

Каждый объект имеет единый минимальный паспорт.

Минимальный паспорт является обязательным для всех объектов.

---

## 3.4. Эволюция

Структура объектов развивается посредством миграций.

Массовое изменение объектов выполняется только массовыми операциями.

---

## 3.5. Управляемость

Изменение множества объектов должно выполняться одной управленческой операцией.

Если изменение требует ручного изменения каждого объекта, архитектура считается несовершенной.

---

# 4. Инварианты

Следующие правила являются обязательными и не могут нарушаться.

1. Каждый объект имеет уникальный идентификатор.

2. Идентификатор объекта никогда не изменяется.

3. Каждый объект имеет паспорт.

4. Паспорт объекта всегда располагается в начале файла.

5. Все изменения структуры объектов выполняются посредством миграций.

6. Массовое ручное изменение объектов не допускается.

---

# 5. Структура объекта

Каждый объект состоит из двух частей.

## Паспорт

```yaml
---
id:
type:
status:
title:
source:
created:
tags:
---
```

## Содержимое

После YAML располагается содержимое объекта.

Структура содержимого определяется типом объекта.

---

# 6. Обязательные поля

| Поле | Назначение |
|------|------------|
| id | Уникальный идентификатор объекта |
| type | Тип объекта |
| status | Состояние жизненного цикла |
| title | Наименование объекта |
| source | Источник возникновения |
| created | Дата регистрации |
| tags | Дополнительные метки |

---

# 7. Эволюция стандарта

Изменение настоящего стандарта допускается только посредством выпуска новой версии стандарта.

Если изменение требует преобразования существующих объектов, одновременно выпускается соответствующая миграция (MIG).

Любое массовое изменение объектов должно быть воспроизводимым и автоматизированным.

---

# 8. Каноны

## Канон 0001

Любой объект CMOC должен быть зарегистрирован прежде, чем он может быть использован.

---

## Канон 0002

Объект важнее файла.

Файл является способом хранения объекта, но не самим объектом.

---

## Канон 0003

Архитектура считается качественной, если изменение любого количества объектов выполняется одной управленческой операцией.
