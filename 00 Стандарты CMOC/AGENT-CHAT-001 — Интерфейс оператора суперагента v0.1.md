# AGENT-CHAT-001 — Интерфейс оператора суперагента v0.1

## Назначение

AGENT-CHAT-001 задаёт человеко-машинный интерфейс для запуска производственных машин CMOC через чат.

Цель интерфейса: оператор не управляет Python, API, endpoint или внутренними структурами. Оператор задаёт Источник, TASK и действие; Superagent выполняет согласованный производственный маршрут и возвращает подтверждение.

## Минимальная команда

Рекомендуемый формат:

> АГЕНТ. <SOURCE_ID>. <TASK>. <ACTION>.

Пример:

> АГЕНТ. SRC-002. M01. ЗАПУСК.

Минимальная семантика:

- SOURCE_ID — идентификатор логического Источника;
- TASK — производственная задача;
- ACTION — команда запуска/продолжения/остановки.

## Рабочий протокол

1. Найти и принять SOURCE_PACKAGE по SOURCE_ID.
2. Проверить полноту и статус пакета.
3. Создать новый BATCH_ID для запуска TASK.
4. Проверить TASK contract.
5. Выполнить MACHINE.
6. Выполнить post-execution QC.
7. Зафиксировать OUTPUT и TRACEABILITY.
8. Выполнить HANDOFF только явно.
9. При несовместимости — REJECT/STOP с причиной.
10. При STOP — создать ESCALATION согласно ESCALATION-CONTRACT-001; не продолжать скрыто.

## Ответ в чате

После каждого запуска оператор получает компактный статус:

- SOURCE;
- TASK;
- BATCH;
- CONTRACT;
- EXECUTION;
- QC;
- OUTPUT;
- TRACEABILITY;
- STATUS.

При ACCEPT явно указывается следующий допустимый шаг, если он известен по контракту.

## Жёсткие правила

- MACHINE ≠ SOURCE ≠ TASK ≠ BATCH.
- Каждый новый TASK получает новый BATCH_ID.
- HANDOFF ≠ автоматическая приёмка.
- Каждый HANDOFF проходит CONTRACT CHECK.
- REJECT не создаёт downstream Batch.
- Никакого silent conversion.
- Никакого скрытого использования предыдущего OUTPUT.
- Никакого скрытого восстановления SOURCE.
- Никакого внешнего знания вместо заявленного источника.
- STOP является корректным результатом.
- ESCALATION не является скрытым продолжением.
- CANONIZATION не выполняется автоматически.
- История производства не переписывается.

## Граница ответственности

AGENT-CHAT-001 является интерфейсом оператора.

Он не заменяет:

- INVARIANT;
- MACHINE;
- TASK CONTRACT;
- SOURCE INTERFACE;
- ORCHESTRATION POLICY;
- QC/EVIDENCE.

Семантическое содержание производится соответствующей MACHINE, а не интерфейсом чата.

## MVP

На MVP-стадии оператор может использовать естественную короткую команду. Система преобразует её в формальные параметры:

SOURCE_ID + TASK + ACTION

и далее действует только в пределах действующих контрактов и политик.
