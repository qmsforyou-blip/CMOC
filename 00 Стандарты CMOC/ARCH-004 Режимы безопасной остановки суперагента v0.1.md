# ARCH-004 — Режимы безопасной остановки суперагента v0.1

## Назначение

ARCH-004 фиксирует два проверенных режима, в которых суперагент обязан прекращать автоматическое производственное движение вместо неявного продолжения.

## Режим 1 — REJECT по контракту

```
INPUT
  ↓
CONTRACT CHECK
  ↓
MISMATCH
  ↓
REJECT
  ↓
STOP
```

Условия:

- тип входа не входит в допустимые входы TASK;
- обязательный входной реквизит отсутствует;
- трассировка отсутствует.

При таком результате downstream TASK не запускается.

Проверено:

`M02 → DISTINCTION_RECORDS → M04 → TYPE_MISMATCH → REJECT`

Evidence: `CONTROL-RUN-013-CONTRACT-REJECT-M02-M04.md`

## Режим 2 — NEEDS_EVIDENCE

```
OUTPUT
  ↓
QC / EVIDENCE CHECK
  ↓
NEEDS_EVIDENCE
  ↓
STOP
  ↓
EXPLICIT OPERATOR DECISION
  ↓
NEW BATCH
  ↓
RECHECK
```

При таком результате машина не должна самостоятельно восстанавливать недостающее основание.

Проверено:

`M07 REL-001 → M08 CAN-001 NEEDS_EVIDENCE → operator decision → new Batch → recheck → PROVISIONAL`

Evidence:

- `CANONIZATION-DECISION-SRC-002-M08-001-CAN-001.md`
- `CANONIZATION-DECISION-SRC-002-M08-002-CAN-001-RECHECK.md`
- `SUPERAGENT-RUN-011-SRC-002-M08-CAN-001-RECHECK.md`

## Общее правило

**Если основание для автоматического продолжения отсутствует, суперагент не компенсирует его догадкой. Он останавливает движение и фиксирует причину.**

Различие:

| Ситуация | Результат | Следующее действие |
|---|---|---|
| Контракт не выполнен | REJECT | STOP; исправить вход/контракт |
| Основание недостаточно | NEEDS_EVIDENCE | STOP; явное решение; новый Batch; RECHECK |

## Связь с инвариантами

- INV-001 — разделение MACHINE / SOURCE / TASK / BATCH.
- INV-002 — HANDOFF не означает автоматическую приемку.
- INV-003 — управляемое исправление через новый Batch.
- ARCH-003 — цикл управляемого исправления.

## Граница доказательства

Оба режима подтверждены на конкретных контрольных сценариях MVP/SRC-002. Универсальность для всех машин и TASK этим документом не утверждается.
