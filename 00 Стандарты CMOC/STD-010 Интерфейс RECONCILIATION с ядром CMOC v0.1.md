# STD-010 — Интерфейс RECONCILIATION с ядром CMOC v0.1

## 1. Назначение

RECONCILIATION — отдельная производственная функция, которая сопоставляет накопленные результаты добычи знания с уже существующим ядром CMOC.

Она не заменяет M01–M08 и не вмешивается в source-only extraction.

## 2. Два производственных контура

### Контур 1 — DISCOVERY / SOURCE PROCESSING

```
SOURCE
  ↓
M01 → M02 → M03 → M04 → M05 → M06 → M07 → M08
  ↓
SOURCE-BOUND OUTPUTS
  ↓
CMOC INTAKE / ЗАГОТОВКА
```

Повторы и кандидаты здесь допустимы и не считаются ошибкой.

### Контур 2 — RECONCILIATION

```
CMOC INTAKE
    +
CMOC CORE
    ↓
RECONCILIATION
    ↓
NEW
EXISTING_EQUIVALENT
EXISTING_RELATED
CONFLICT
NEEDS_REVIEW
    ↓
DECISION
    ↓
CORE UPDATE / INDEX UPDATE / HOLD
```

## 3. Принцип разделения

**Поиск добывает. RECONCILIATION сопоставляет.**

Discovery не обязан устранять дубликаты.

Reconciliation не должна повторно добывать содержание источника.

## 4. Когда запускать RECONCILIATION

Базовый режим для MVP: **после завершения полного логического прохода источника**, когда M01–M08 выполнены в пределах заявленного scope.

Допускаются более ранние или пакетные запуски, если это явно задано TASK/оператором.

Таким образом, Reconciliation не обязана запускаться после каждого extraction record.

## 5. Что является входом

Входом является конкретный накопленный пакет результатов Discovery, имеющий SOURCE_ID, BATCH_ID/lineage, TASK/output type, traceability, статус и набор объектов для сопоставления.

Вход не должен молча заменяться текущим содержимым CMOC.

## 6. Что является эталоном сравнения

RECONCILIATION получает доступ к опубликованному/доступному для сопоставления слою CMOC.

Минимальные области поиска: TERMS / NOMENCLATURE; DISTINCTIONS; FORMULATIONS; CLASSIFICATIONS; PASSPORTS; RELATIONS; CANON.

Черновики и незавершённые кандидаты могут участвовать в сравнении, но их статус должен быть сохранён и не должен автоматически повышаться.

## 7. Результаты сопоставления

### NEW
В ядре не обнаружен эквивалентный объект.

### EXISTING_EQUIVALENT
В ядре обнаружен существующий объект с тем же объектным смыслом. Новый объект не создаётся автоматически.

### EXISTING_RELATED
В ядре найден связанный, но не эквивалентный объект. Новый кандидат сохраняется; возможная связь фиксируется отдельно.

### CONFLICT
Новый результат и существующий объект дают несовместимые основания, определения, типы или отношения. Автоматический выбор одной стороны запрещён.

### NEEDS_REVIEW
Данных недостаточно для надёжного решения о совпадении, различии или конфликте.

## 8. Дубликат ≠ ошибка

Discovery может создать повтор термина, повтор различения, повтор формулировки, повтор кандидата связи или повтор паспорта-кандидата.

Это не является дефектом Discovery.

Дубликат становится предметом RECONCILIATION.

## 9. Индексация

После принятого решения RECONCILIATION может инициировать создание index reference, связывание нового кандидата с существующим объектом, регистрацию alias, обновление индекса поиска, регистрацию конфликта или регистрацию NEEDS_REVIEW.

Изменение канонического содержания выполняется отдельной операцией с собственной трассировкой.

## 10. Накопление истории

RECONCILIATION не удаляет исходные результаты Discovery.

```
SOURCE
→ DISCOVERY BATCH
→ CANDIDATE
→ RECONCILIATION RUN
→ MATCH / DECISION
→ CORE ACTION
```

Тем самым ядро накапливает не только принятые объекты, но и историю сопоставлений.

## 11. Минимальная форма

`DISCOVERY_OUTPUT + CMOC_QUERY → RECONCILIATION → DECISION → CORE_ACTION`

## 12. Граница автоматизации

RECONCILIATION может автоматически искать кандидатов на совпадение, группировать очевидные дубли, строить candidate matches, индексировать и поднимать NEEDS_REVIEW.

RECONCILIATION не должна без отдельного правила переписывать историю, превращать PROVISIONAL в CANONICAL, разрешать CONFLICT, удалять дубликаты как исторические записи или менять смысл исходного source-bound результата.

## 13. Связь с архитектурой

```
SOURCE
  ↓
DISCOVERY MACHINES
  ↓
CMOC INTAKE
  ↓
RECONCILIATION MACHINE
  ↓
CMOC CORE / INDEX
```

## Evidence boundary

STD-010 является архитектурной спецификацией следующего контура. Сам RECONCILIATION runtime и его контрольные прогоны этим документом ещё не подтверждены.
